# 現状報告と引き継ぎ事項（2026-09-24）

## 対象と公開状態

- 本体: [har1101/strands-lambda-durable-functions](https://github.com/har1101/strands-lambda-durable-functions)。Strands Agents TypeScript と AWS Lambda durable functions をつなぐ非公式のコミュニティ拡張。
- 既存の GitHub Release は `v0.2.0`。今回のセキュリティ修正は `CHANGELOG.md` の **Unreleased** に記載。`package.json` はまだ `0.2.0` のままであり、修正済みの新しいタグ、Release、npm パッケージは作っていない。`main` のソースを使う場合と、`v0.2.0` の tarball を使う場合を混同しないこと。
- 関連するサンプルアプリは別リポジトリ [har1101/strands-lambda-durable-ts](https://github.com/har1101/strands-lambda-durable-ts)。このリポジトリでは変更していない。

## このセッションで反映した変更

1. `src/offload.ts`: 小さい JSON 値の `$offload`/`$inline` をデータのまま扱い、ポインターは現在の実行 ARN とオペレーション ID から導かれるキーだけを読む。新しいポインターには SHA-256 を記録し、読み込み時に照合。旧ポインターも読み込み可能。
2. `src/s3.ts`: S3 バケット所有者の検証、SSE-KMS 設定、チェックポイントの読み書きの最大サイズ（既定 64 MiB）。IAM とバケットポリシーによるアクセス制限も利用側で必要。
3. `src/codec.ts`, `src/tool.ts`: チェックポイント形式を `schemaVersion` 4 に更新。`$bytes`/`$esc` に見える通常の JSON はエスケープして保持し、旧 v1〜v3 も読む。ツールの記録に toolUseId とツール名を含め、リプレイ時に照合。
4. `src/model.ts`, `src/executor.ts`, `src/scope.ts`, `src/workflow-tool.ts`: 同一応答・ターン内の重複 `toolUseId` を拒否。異なるターンやネストしたワークフローツールで ID が再利用されても、各ツール呼び出しの冪等キーは異なる SHA-256 ダイジェストになる。**従来の `<execution ARN>#<toolUseId>` 形式から変更**。
5. `src/events.ts`, `src/tool.ts`, `src/mcp.ts`: ツール結果・進捗・割り込み理由をライブイベントに含めるには `eventDetails: true` が必要。MCP の `filter` を追加し、実行前に記録済み入力スキーマとの相違を検出。
6. `.github/workflows/{ci,release}.yml`, `.github/dependabot.yml`: Actions を SHA 固定、依存インストール時のスクリプト無効化、build と publish の権限・秘密情報を分離。Release に SHA256SUMS と build provenance attestation を添付し、npm 公開は `npm` environment と step 単位のトークン（または Trusted Publishing）を使用。
7. `README.md`, `README.ja.md`, `CHANGELOG.md`, `SECURITY.md`: 厳密な承認値判定、永続化データとライブイベントの公開範囲、オフロード、MCP、配布物の検証と脆弱性報告手順を追記。`test/security.test.ts` 等で回帰を確認。

## 実施済みの検証

- ローカル: `npm run typecheck`、`npm test`（28/28）、`npm run build`、`npm pack --dry-run`（43 files）、`actionlint -shellcheck= .github/workflows/*.yml` は成功。新設のセキュリティ 7 件と MCP 2 件は修正前には失敗することも確認した。
- AWS（ap-northeast-1、アカウント `064212132988`）: 一時的な Lambda durable function と S3/KMS を使って、修正前の `$offload` 経由の別オブジェクト読み取り、マーカー型データの変換、冪等キーの衝突を再現。修正後はポインターをデータのまま保持し、マーカー型 JSON と各呼び出しのキーを区別。重複 ID の拒否、`{"approved":"false"}` の却下と `{"approved":true}` の承認、S3 サイズ制限/所有者確認/SSE-KMS、実際の Bedrock Claude Haiku 4.5 と並列ツール、ツール結果を含めないライブイベントを確認。
- S3 内のオフロード済みオブジェクトを改変すると SHA-256 不一致で読み込みに失敗した。**AWS durable SDK は `SerdesFailedError` の実行を繰り返し再試行したため、テスト実行を手動停止した**。単発で最終的な FAILED 状態になるわけではない。
- AWS 検証用の Lambda、IAM ロール、S3 バケット、ロググループは削除済み。常設のサンプルアプリや既存スタックは変更していない。

## 未決事項・次の操作

- **GitHub の設定**: 2026-09-24 時点で Private vulnerability reporting は `enabled: false`。`SECURITY.md` の非公開報告リンクを使えるように、リポジトリの Settings → Security で有効化すること。公開 Issue で脆弱性の詳細を受け取らない。
- **npm 公開設定**: `npm` environment は未作成（API 404）、`NPM_TRUSTED_PUBLISHING` 変数も未設定（API 404）。将来公開する際は environment の required reviewers を設定し、npm 側で `release.yml` を trusted publisher に登録してから変数を `true` にする。トークン方式なら `NPM_TOKEN` を公開ステップにのみ渡す。現時点では新タグを push しても新たな npm 公開の保証はない。
- **配布**: 修正済み版を利用者へ配る場合は、互換性破壊（冪等キー、イベント詳細の opt-in）を考慮してバージョンを上げ、タグと Release を作ること。実行中の旧バージョンの durable execution を新コードへ無条件に切り替えず、公開済みバージョンまたはエイリアスに固定する。
- **サンプルアプリ**: `har1101/strands-lambda-durable-ts` の `ChatView` は `tool` イベントの `result`/`text` を利用している。修正済み版へアップグレードし、それらを引き続き表示する設計なら `DurableTool`/MCP の `eventDetails: true` を明示し、表示先の認可を点検する。今回は別リポジトリを変更していない。

詳細な理由と再現の落とし穴は [learnings](./2026-09-24-learnings.md) を参照。
